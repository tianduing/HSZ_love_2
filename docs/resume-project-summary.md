## 项目背景

传统 AI 学习产品普遍存在 3 个问题：

1. 只提供单轮问答，缺少从学习路线到复习巩固的完整闭环。
2. 结构化学习状态与非结构化材料内容割裂，用户导入 PDF 后很难把资料真正用进答题反馈。
3. 学习过程不可追踪、不可解释，用户无法快速定位自己到底卡在概念理解、应用落地还是表达完整度。

因此我把项目定位成一个资料驱动的桌面学习助手，目标不是直接“给答案”，而是把学习材料整理成可推进、可追溯、可复盘的项目化学习流程。

## 技术栈

- 客户端：Electron、Node.js、Vanilla JavaScript、HTML/CSS
- AI 能力：OpenAI 兼容大模型接口，支持自定义 Base URL、模型名与本地配置持久化
- 文档能力：PDF.js，用于 PDF 解析、页级预览与文本分块
- 数据与检索：本地 JSON 持久化、自研轻量检索与引用引擎
- 交互能力：可编辑学习路线、答题评估、复习调度、弱项诊断、项目管理

## 功能开发

1. 设计可扩展学习路径引擎：围绕通用学习、强化追问、算法刷题、论文阅读、项目实战 5 类场景构建训练模板，并结合入门 / 中级 / 进阶 3 档学习者画像，为不同基础用户动态调整问题难度、追问深度与过关阈值。
2. 构建资料驱动问答链路：接入 PDF.js 完成文档导入、页级预览与文本分块，支持最多 12 页预览与 64 段内容检索，并把材料出处绑定到学习路线、答题反馈与复习回看 3 个关键环节。
3. 实现学习闭环与复习调度：围绕主线答题与复习答题建立结构化评估记录，支持随机 / 当前项目 / 薄弱点 / 最近完成 4 种复习模式，并通过弱项聚类把问题归因到主干理解、应用落地、表达完整度 3 类核心能力。
4. 完成桌面端产品化能力：补齐项目管理、标签分类、归档、答题时间记录、学习统计与本地配置保存，使项目从单次原型升级为可持续使用的桌面工具。

## 量化结果

以下表述基于当前代码实现范围，可直接用于简历，整体更稳妥：

- 搭建 6 个核心模块：项目管理、路线生成、PDF 导入、答题评估、复习回看、弱项诊断，完成 AI 学习产品桌面端从 0 到 1 落地。
- 设计 5 类训练模板、3 档学习者画像、4 种复习模式，单项目支持 5-30 个主线问题自动拆解。
- 打通 3 条资料引用链路：路线生成、答题反馈、复习回看，实现基于页码的材料回溯与证据展示。
- 构建本地文档处理能力，支持 12 页预览与 64 段文本分块，提升长文档学习场景下的材料可用性。

## 简历版写法

### 版本一：适合中文简历的 3 条要点

- 基于 Electron、Node.js 与 OpenAI 兼容大模型接口开发 AI 学习助手，围绕长期学习场景构建“资料导入 - 路线生成 - 问答评估 - 弱项诊断 - 复习回看”闭环，完成桌面端产品从 0 到 1 搭建。
- 设计 5 类学习教练模板与 3 档学习者画像，支持单项目 5-30 个主线问题自动拆解，并通过多轮追问、结构化评分与项目级持久化提升学习路径的可执行性与可复盘性。
- 接入 PDF.js 与自研轻量检索 / 引用引擎，实现页码级材料解析、12 页预览、64 段文本分块及 3 条引用链路回溯，在答题反馈与复习环节提供可追溯证据支撑。

### 版本二：更像面试回答的浓缩版

我做的是一个资料驱动的 AI 学习助手，不是普通聊天框。核心思路是把 PDF 学习材料、AI 路线生成、答题评估、弱项诊断和复习调度打成一个闭环。技术上我用 Electron 做桌面端，接入 OpenAI 兼容模型接口和 PDF.js，再加一套本地轻量检索与引用机制，让模型反馈不只是“给评价”，而是能回到具体材料页。现在项目已经覆盖 6 个核心模块、5 类训练模板、4 种复习模式，单项目支持 5-30 个主线问题自动拆解。
