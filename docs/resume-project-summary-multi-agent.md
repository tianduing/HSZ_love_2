## 项目背景

企业级学习辅导系统与智能教育产品普遍面临三个核心问题：

1. 复杂学习意图识别准确率低于 `60%`，用户问题常混合概念理解、刷题求解、材料检索、情绪化表达与知识迁移，传统单 Agent 问答模式难以稳定分流。
2. 学习领域结构化数据与非结构化数据割裂，结构化侧包括用户画像、知识点掌握度、错题记录、课程关系与任务进度，非结构化侧包括 PDF 教材、讲义、论文、笔记与题解，导致系统无法把“学情状态”与“材料证据”真正联动。
3. 长尾复杂问题依赖人工辅导或多轮手动介入，复杂学习场景下的解释、追问、检索、诊断与复习设计成本高，人工辅学时间占比可超过 `40%`，缺少可扩展的新一代 Multi-Agent 学习解决方案。

因此，项目目标是构建新一代 `Multi-Agent` 学习助手：不再只做单轮回答，而是围绕学习意图识别、学情诊断、知识检索、路径规划、复习调度和多模态解析，搭建可扩展的智能学习编排系统。

## 项目集成

- 大模型层：`DeepSeek V3`、`DeepSeek R1` 在线 API，以及通过 `Ollama` 部署的开源模型
- Agent 编排：基于 `LangGraph` 构建 Multi-Agent 架构，使用 `LangChain` 组件化接入模型、检索器与工具链
- 知识治理：`Neo4j` + `neo4j-graphrag` + `Microsoft GraphRAG`
- 数据底座：`MySQL` 结构化学习数据、离线文档知识库、学习轨迹与错题记录
- 客户端：`Electron` 桌面端，承载学习项目管理、学习对话、资料导入、复习回看与结果展示

## 功能开发

1. 基于 `LangGraph` 构建可扩展学习意图识别网络，覆盖 `6` 类复杂学习场景：通过动态情绪识别与安抚策略处理闲聊 / 焦虑类表达；对概念理解、项目实战与论文阅读场景采用多轮追问机制；对实时资料查询启用缓存优先策略提升响应效率；并接入多模态模型支持截图、题面、图文混合材料解析。
2. 设计混合知识治理引擎，预构建 `100+` 个 `Cypher` 查询模板，覆盖知识点依赖、错题归因、先修关系、资料定位、学习路径推荐等 `90%` 高频学习场景，同时完成 `MySQL -> Neo4j` 自动映射，把结构化学情数据与非结构化学习材料统一进图谱系统。
3. 结合 `Microsoft GraphRAG` 与离线文档库搭建混合知识底座，把教材、论文、讲义、笔记、题解与用户历史学习记录接入统一检索层，支持“学情状态 + 资料证据 + 路径规划”的联合推理。
4. 通过 `LangGraph Map-Reduce` 构建并行工具执行机制，基于 `neo4j-graphrag + LLM` 自动生成 `Cypher` 查询流程，同时设计 Cypher 语法、关系方向、权限边界与空结果回退校验链路，并接入大模型完成查询异常、自我纠正与映射校验。
5. 围绕学习闭环设计多 Agent 协同链路：意图识别 Agent 负责分流，资料检索 Agent 负责定位证据，学情诊断 Agent 负责定位薄弱点，路径规划 Agent 负责生成学习路线，复习调度 Agent 负责基于错题与遗忘曲线生成回看任务。

## 项目成果

- 复杂学习意图识别准确率从 `< 60%` 提升至 `85%+`
- `6` 类核心学习场景命中率达到 `90%+`
- 闲聊 / 情绪类意图误判率降至 `5%` 以内
- 搭建 `Neo4j` 混合知识治理引擎，开发 `100+` 个 `Cypher` 模板，覆盖 `90%` 高频学习查询
- 自动生成 `Cypher` 查询错误率从 `12%` 降至 `1.5%` 以下

## 简历版写法

### 版本一：高含金量 3 条要点

- 基于 `DeepSeek V3 / R1` 在线接口与 `Ollama` 本地开源模型，结合 `LangGraph + LangChain` 设计 Multi-Agent 学习系统，面向复杂学习场景构建“意图识别 - 资料检索 - 学情诊断 - 路径规划 - 复习调度”智能闭环。
- 构建覆盖 `6` 类复杂学习场景的可扩展识别网络，通过动态情绪分析、多轮追问、缓存优先检索与多模态解析策略，将复杂学习意图识别准确率从 `< 60%` 提升至 `85%+`，核心场景命中率达到 `90%+`。
- 搭建 `Neo4j` 混合知识治理引擎，完成 `MySQL -> Neo4j` 自动映射，并结合 `GraphRAG` 构建离线学习知识库；预构建 `100+` 个 `Cypher` 模板覆盖 `90%` 高频场景，使自动生成 `Cypher` 查询错误率从 `12%` 降至 `1.5%` 以下。

### 版本二：更像面试回答的浓缩版

这个项目我想把普通学习助手升级成真正的 Multi-Agent 学习系统。核心不是“回答一道题”，而是先识别用户当前到底是在提问概念、查资料、做题、读论文，还是情绪卡住了；然后把结构化学情数据和非结构化学习材料一起接进来，再由不同 Agent 分别负责检索、诊断、路径规划和复习调度。技术上我会用 DeepSeek + Ollama 做模型层，LangGraph 做编排，Neo4j 和 GraphRAG 做知识治理。这样项目的价值就不只是一个桌面 AI 工具，而是一个可以继续往教育 Agent 平台走的系统型项目。

## 如何从当前项目继续落地到这个版本

1. 在现有 Electron 客户端上增加 `LangGraph` 编排层，把当前单链路问答升级成多 Agent 调度。
2. 把当前 PDF 分块与引用能力升级为混合检索层，接入 `Neo4j` 知识图谱与 `GraphRAG`。
3. 引入学习意图分类、情绪识别、学情诊断与复习调度四类核心 Agent，把当前“答题反馈”升级为“策略化诊断”。
4. 增加真实评测集与日志指标，补齐意图准确率、检索命中率、复习召回率与自动查询错误率等可量化结果。

## 建议

如果你要把这个项目顶替客服项目，我建议简历里直接放这一版叙事，但面试时要分清两层：

- 当前已做：Electron 客户端、学习路线、PDF 导入、轻量检索、引用回挂、复习与弱项诊断
- 目标升级：DeepSeek / Ollama、LangGraph Multi-Agent、Neo4j、GraphRAG、Cypher 自动生成与校验链路

这样写法会显得你有系统设计能力和明确演进路线，而不是只会堆前端小功能。
