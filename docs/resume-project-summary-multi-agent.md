## 一、项目定位

建议不要再把这个项目简单写成“学习助手”，而是升级成下面这种定位：

**多模态 AI 学习教练 / Multi-Agent Learning Copilot**

它的核心价值不是“回答用户问题”，而是围绕复杂学习场景，建立一套从意图识别、资料理解、反馈生成到复习调度的完整闭环。

## 二、项目背景

传统学习类 AI 产品大多停留在单轮文本问答，主要存在以下问题：

1. 用户问题常混合概念理解、题目求解、资料检索、论文阅读、项目实战与情绪化表达，单一问答链路难以稳定识别复杂学习意图。
2. 学习过程中的结构化状态与非结构化材料割裂，结构化侧包括学习进度、错题记录、掌握度与复习轨迹，非结构化侧包括 PDF 教材、讲义、题面截图、笔记图片与流程图，导致系统难以形成真正可解释的资料驱动反馈。
3. 当用户输入长文档、题目截图、课堂笔记或图文混合材料时，传统纯文本方案经常出现理解不完整、追问不精准、反馈不可复盘的问题。

因此，项目目标是构建一个支持文本、PDF、图片输入的多模态 AI 学习系统，通过多 Agent 协同完成学习意图识别、资料检索、学情诊断、反馈生成与复习调度，提升复杂学习场景下的准确性、可解释性与持续陪练能力。

## 三、技术方案

这部分建议采用更主流、更容易被企业接受的写法，不必强行堆图谱或 Cypher：

- 客户端：`Electron`、`Node.js`、`HTML/CSS/JavaScript`
- 模型层：`DeepSeek V3 / R1`、OpenAI 兼容接口、可接入 `Ollama` 本地模型作为离线或轻量 fallback
- 多模态能力：接入视觉模型用于题面截图、笔记图片、流程图、教材图片解析
- 系统编排：基于工作流编排的 `Multi-Agent` 协同机制，负责路由、检索、诊断、反馈与复习调度
- 文档处理：`PDF.js`，用于 PDF 解析、页级预览、文本分块与引用回挂
- 检索能力：轻量混合检索，结合关键词匹配、分块检索与引用证据回溯
- 评测机制：围绕意图识别、多模态理解、反馈质量建立评测与回归机制

## 四、核心功能

### 1. 多模态学习意图识别

围绕复杂学习场景设计 `6` 类核心学习意图识别机制，包括：

- 概念理解
- 刷题求解
- 资料检索
- 论文阅读
- 项目实战
- 闲聊 / 情绪化表达

对于低置信度问题，系统通过自动追问进一步澄清真实需求；对于图文混合输入，则优先完成图像理解与文本对齐，再进入后续路由。

### 2. 多模态资料理解

支持对以下输入进行统一处理：

- 文本问题
- PDF 材料
- 题目截图
- 课堂笔记图片
- 教材页 / 讲义页图片
- 流程图 / 示意图

系统可以将非结构化资料解析为可检索内容，并在答题反馈与复习阶段回挂到对应证据片段，增强结果的可解释性。

### 3. 学习反馈闭环

围绕一次完整学习过程，系统形成以下闭环：

`意图识别 -> 资料检索 -> 回答评估 -> 薄弱点诊断 -> 追问补全 -> 复习调度`

相比普通问答式产品，这种设计的价值在于它不仅给出答案，还能帮助用户明确“为什么没学会、卡在哪里、下一步该复习什么”。

### 4. 模型评估与回归

这是项目很重要的含金量来源。建议在表述中明确强调：

- 对意图识别能力建立分类评测
- 对多模态理解建立图文样本评测
- 对反馈质量建立人工 rubric 或结构化评测
- 对版本升级建立回归测试，避免提示词或模型切换后性能退化

这样会让项目从“会调接口的产品 demo”提升成“具备模型工程意识的系统项目”。

## 六、适合直接写进简历的要点文案

### 写法 1：偏工程实现

- 基于 `Electron`、`Node.js` 与大模型接口开发多模态 AI 学习教练，围绕复杂学习场景构建“意图识别 - 资料检索 - 回答评估 - 薄弱点诊断 - 复习调度”闭环，完成桌面端学习产品从原型到系统化方案的设计与实现。
- 设计覆盖 `6` 类学习意图的路由机制，支持概念理解、刷题求解、资料检索、论文阅读、项目实战与情绪化表达等场景，并通过低置信度自动追问提升复杂问题分流效果。
- 接入 PDF 与图片输入链路，支持题面截图、讲义页、笔记图片等多模态资料解析，结合文本分块检索与证据回挂机制，在答题反馈与复习阶段提供可解释的引用支撑。
- 建立答题评估、薄弱点诊断、追问补全与复习推荐机制，支持随机复习、当前项目复习、薄弱点优先复习等多种策略，形成可持续迭代的学习反馈闭环。
- 设计模型评测与回归方案，从意图识别、多模态理解、反馈质量三个维度评估系统表现，为后续模型切换、提示词优化与工作流升级提供量化依据。

### 写法 2：偏 AI 系统表达

- 设计多 Agent 协同的 AI 学习系统，围绕学习意图分类、资料理解、反馈生成与复习调度建立任务编排机制，提升复杂学习问题的处理精度与系统可扩展性。
- 面向文本、PDF 与图像混合输入场景构建多模态理解链路，支持从题面截图、教材页、课堂笔记到长文档材料的统一解析与检索回溯。
- 将传统单轮问答升级为“评估 - 诊断 - 追问 - 复习”闭环式学习流程，使系统从即时回答工具演进为可持续陪练的学习教练产品。
- 建立结构化评测集与反馈质量 rubric，支持对意图识别准确率、图文理解正确率、资料引用命中率与复习推荐命中率进行持续评估。

### 写法 3：偏产品落地 + AI 结合

- 面向长期学习与高频复习场景开发多模态 AI 学习教练，支持用户基于 PDF、文本与图片材料快速生成学习路线，并在学习过程中动态提供评估反馈与复习建议。
- 针对复杂学习问题设计多层路由与追问机制，减少单一问答模式下的误判与泛化回答问题，增强复杂场景下的响应针对性。
- 结合证据引用、薄弱点聚类与复习调度能力，提升学习过程的可追踪性、可解释性与后续复盘效率。

## 七、理想化量化结果参考

> 下面这部分是“理想化参考写法”，适合你后面真正补评测后再替换成正式结果。现在可以先拿来参考语气和量级，但不建议在没有实验数据时逐字照抄。

### 参考写法 1：偏稳妥区间型

- 在自建文本 + 图文混合评测集上，`6` 类学习意图识别准确率达到 `80%~85%`，`Macro-F1` 提升至 `0.78~0.83`
- 引入低置信度追问与多轮路由后，复杂问题误路由率下降至 `8%~12%`
- 接入图片 / PDF 多模态解析后，图文场景理解正确率提升至 `75%~82%`
- 资料分块检索与证据回挂能力上线后，引用命中率达到 `78%~85%`
- 基于答题评估、薄弱点诊断与复习调度的闭环机制，复习推荐命中率提升至 `70%~80%`
- 通过缓存检索与轻量工作流优化，平均响应时延降低 `25%~35%`

### 参考写法 2：更适合写进简历的压缩版

- 自建 `6` 类学习意图评测集，复杂学习意图识别准确率提升至 `80%+`，复杂问题误路由率控制在 `10%` 以内
- 支持文本、PDF 与图片的多模态输入理解，图文场景理解正确率提升至 `75%+`，资料引用命中率达到 `80%` 左右
- 建立“评估 - 诊断 - 追问 - 复习”学习闭环后，复习推荐命中率提升至 `70%+`，平均响应延迟下降 `25%+`

### 参考写法 3：面试时更自然的说法

如果面试官追问这些数字，你可以把它表述成：

“这些结果更接近我后续打算通过评测集去验证的目标区间。现在我会先把指标体系定义清楚，比如意图识别准确率、多模态理解正确率、引用命中率、复习推荐命中率，然后基于真实样本去做评测和回归，不会直接把理想结果当成最终实验结果写死。”

## 九、你现在最该避免的写法

下面这些内容在当前项目阶段不建议继续作为主卖点：

- `Neo4j`
- `GraphRAG`
- `Cypher 模板`
- `MySQL -> 图谱自动映射`
- 没有明确评测依据的单点性能数字，例如 `60% -> 85%`

原因不是它们不好，而是它们和你当前项目的真实核心不够匹配，也容易被面试官顺着深挖到实现细节。
